# AI lists

## Global lists

Written by `tools/o2r_packer/pack_ai_lists.py` into the objects archive at
`ai/globals` (`OBLB`, ASCII text). They are the decomp's `g_GlobalAILists`
(ids 0 to 17, the scripts any character can be given), read from the US ROM's
compressed data segment (the decomp's `scripts/extract_cdata.sh` inflates the
same bytes) because the decomp builds them with macros a host compiler
expands differently.

One line per list: the list id, a tab, and the list's bytes as hex. A list runs
to the next list's start (it may carry zero padding after its end command).

## Setup lists

A stage's setup file holds its own lists (`docs/formats/goldeneye-stage-setup.md`,
header word 5): `{u32 list offset, s32 id}` records ended by a null offset,
each list running to its end-of-list command. Ids 1025 and up are the stage's
character lists; ids from 4096 run in the background, one hidden character
each.

## Commands

A list is a run of commands: an opcode byte followed by the command's fields,
big-endian and packed with no padding. `src/level/AiCommands.h` (generated by
`tools/ai_commands/gen_ai_commands.py`) has every opcode, each command's size
and its fields' offsets and types. `AI_PRINT` is the one command of no fixed
size: its string runs to a NUL byte.

## Waypoints, groups and patrol paths

Setup header words 0, 1 and 4. Waypoints are 16-byte records `{s32 pad, u32
neighbours offset, s32 group, s32 dist}` ended by a negative pad; groups are
12-byte records `{u32 neighbours offset, u32 waypoints offset, s32 dist}` ended
by a null neighbours offset; patrol paths are 8-byte records `{u32 waypoints
offset, u8 id, u8 loop, u16 unused}` ended by a null offset. Every array they
point at is a run of `s32` ended by -1.
